## D08 — 최근 기록과 독립 캠페인 업적 분리 (2026-10-09)

- 대안: 완료 기록 무제한 보관 / 과거 점수·성공 메타데이터에서 업적 추정 / 최근 기록과 독립적인 검증 가능한 승리 증거 3개 보관.
- 결정: 기존 `pocket-city-v1` 키에 `achievements`를 추가합니다. 임무별 첫 v2 승리의 버전·임무·코드·최대 20행동만 저장하고, 로딩·저장 시 순수 재생으로 승리·임무 일치를 검증합니다. 최근 완료 메타데이터 10개와 진행 중 판 1개는 별도로 유지합니다. 저장된 보드·점수·성공 주장을 업적 증거로 받지 않으며 v1과 행동 없는 과거 v2 완료 기록을 업적으로 이관하지 않습니다. 업적은 초기화 또는 브라우저 저장 삭제까지 유지합니다.
- 결정: 모든 임무를 바로 선택하는 정책을 유지합니다. 다음 임무 추천만 독립 업적에서 계산합니다. 개인 JSON 입력/출력은 최대 32,768자이며 허용 필드만 남깁니다. 초기화는 이 게임의 개인 키만 삭제하고, 저장 불가·복원 불가·삭제 실패는 짧게 알립니다.
- 이유: 기록 순환과 캠페인 진도를 분리하면서 최대 보존량과 재현성을 명확히 합니다. 업적에 추가 완료 날짜·사용자 정보가 필요하지 않습니다. 순수 campaign.js와 model.js는 UI/storage를 호출하지 않습니다.

## D09 — 갤러리 최소 로컬 요약 (2026-10-09)

- 맥락: 사용자가 모든 앱 공통 연동 계약으로 `web-lab-progress-v1`의 최소 기기 요약을 승인했습니다. 이 작업자는 pocket-city만 수정하며 갤러리 코드나 다른 저장소를 수정하지 않습니다.
- 대안: 갤러리에서 개인 행동 읽기 / 방문·예시·힌트를 완료로 계산 / 실제 승리 후 독립 업적 수만 공유.
- 결정: 실제 v2 승리 후 개인 기록 저장에 성공한 경우에만 `progress.js`가 own `apps["pocket-city"]={completed,total:3,updatedAt}`를 read-modify-write합니다. completed는 검증한 독립 업적 수이며 중복 승리 횟수가 아닙니다. updatedAt은 이번 쓰기의 실제 ISO 시각입니다. 처음 보기·건설 미리보기·재개·실패에는 쓰지 않습니다. 이름·코드·행동·보드·파일·점수는 요약에 넣지 않습니다.
- 결정: 문자 그대로 지정한 15개 repo ID와 root/entry의 정확한 필드만 허용합니다. 정수 `0 <= completed <= total <= 1000`, 유효한 정규 ISO 시각, 8,192자 이하 입출력을 검사합니다. 잘못된 JSON·크기·필드·ID·storage 접근/할당 실패에는 기존 aggregate를 교체하지 않습니다. 다른 앱 항목은 보존하며 own 초기화는 pocket-city 항목만 제거합니다. aggregate가 손상되어 제거하지 못하면 부분 실패를 화면에 알립니다.
- 이유: 갤러리가 캠페인 달성 수를 보여주는 데 개인 재생 데이터는 필요하지 않습니다. 기기 origin 경계 안에서 제한된 수량만 공유하고, 다른 서비스의 데이터 손실을 막습니다. 서버·랭킹·외부 연결은 추가하지 않습니다.
- 영향 파일: dist/src/progress.js·app.js, test/progress.test.js·ui.test.js, architecture.md, README.md.
- 후속 검토: 메인이 동일 origin에서 갤러리 계약의 15개 ID와 실제 읽기·초기화를 검증합니다. 별도 포트의 개발 서버는 저장소가 공유되지 않습니다. malformed aggregate는 자동 복구하지 않으므로 실패 안내를 확인합니다.

- 대안: 예전 행동을 새 규칙으로 강제 변환 / 저장 전체 삭제 / 완료 기록 보존과 진행 재생의 버전 검사.
- 결정: 기존 기기 저장 키를 유지하고 v2 진행에 버전·임무·코드·행동만 저장합니다. 완료 기록은 버전·임무·성공 여부·코드·점수·완료 시각을 저장합니다. v1 완료 기록은 따로 표기하고 시간순으로 표시합니다. 버전이 다른 진행은 안내 후 이어하지 않습니다. 기록 삭제를 유지하고 최대 완료 10개 + 진행 1개를 유지합니다. 단계 성공 표시는 최근 완료 기록에서 계산하며 별도 영구 업적·사용자 식별자를 추가하지 않습니다.
- 이유: 규칙 재현성과 기존 완료 기록을 보존하면서 추가 보존 범위·서버·외부 연결을 만들지 않습니다. 세 임무를 모두 즉시 선택 가능하게 하여 저장 불가 환경에서도 진행을 막지 않습니다.
- 영향 파일: dist/src/model.js, dist/src/app.js, dist/index.html, README.md, test/model.test.js.
- 후속 검토: 브라우저에서 실제 v1/v2 저장, 차단된 localStorage, 새 판 확인 취소, 진행 재로딩·삭제를 메인 담당자가 확인해야 합니다. 개인정보·정적 호스팅·CSP 경계와 순수 모델/UI 분리는 유지합니다. 커밋·푸시·배포·DB 생성은 이번 범위 밖입니다.

## D07 — 포커스 미리보기와 완료 버튼 대비 (2026-10-09 QA 후속)

- 맥락: 메인 브라우저 QA에서 칸의 키보드 포커스는 남아 있는데 스크롤 관련 pointerleave가 정산 미리보기를 기본 설명으로 지웠습니다. 완료 패널에서는 기본 버튼의 `color: inherit`가 흰 패널 글자색을 상속하여 흰 버튼에 흰 글자를 표시했습니다.
- 대안: leave/blur 조건만 각각 추가 / 마지막 칸 인덱스를 저장 / 현재 DOM의 포커스·호버 대상을 매번 조회. 버튼은 전역 색 변경 / 완료 패널에만 명시적 대비 지정.
- 결정: 현재 판 안의 활성화된 포커스 칸을 우선하고, 없으면 현재 호버 칸, 둘 다 없으면 기본 설명을 표시합니다. enter/focus/leave/blur와 렌더 완료가 같은 갱신 함수를 사용합니다. 교체된 칸의 지연 이벤트도 현재 판만 조회합니다. `#endgame button`에 기본·hover·focus-visible 글자/배경색과 포커스 외곽선을 명시합니다.
- 이유: 포인터와 키보드 이벤트 순서에 관계없이 현재 조작 대상을 설명하고, 저장한 이전 DOM/인덱스에서 생기는 오래된 미리보기를 피합니다. 버튼 대비 변경 범위를 완료 패널로 제한합니다. 게임 규칙·점수·저장 형식은 변경하지 않습니다.
- 영향 파일: dist/src/app.js, dist/styles.css, test/ui.test.js, docs/verification.md.
- 후속 검토: 실제 스크롤·혼합 입력·버튼 hover/focus 렌더링은 메인 담당자가 수정 후 브라우저에서 재확인합니다. Node DOM 대역의 실제 앱 콜백 회귀 시험과 CSS 대비 계산은 브라우저·이미지 QA의 대체 증거가 아닙니다.
