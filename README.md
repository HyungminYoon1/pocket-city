# POCKET CITY — 작은 땅, 큰 선택

[사이트 열기](https://hyungminyoon1.github.io/pocket-city/)

5×5 땅에 주택·상점·공원·발전소·도로·진료소를 배치하는 20턴 도시 전략 게임입니다. 규칙 v2에서는 점수보다 임무 성공이 먼저입니다. 기반시설을 연결하고 주민 신뢰를 지키며 예고된 위기에 대비하세요.

- 세 임무: 연결되는 동네 → 폭염 속 정원 도시 → 출근길의 약속. 첫 임무 성공 후 다음 임무로 같은 코드 도전 가능하며 모든 임무는 바로 선택할 수 있습니다.
- 중앙 도로와 이어진 도로망만 시설을 연결하고 통행 용량을 제공합니다. 단절 발전소는 전력을 공급하지 못합니다.
- 상점 수입은 도로·전력·연결 주민에 달려 있습니다. 공원은 인접 주거를, 진료소는 거리 2 이내의 주거를 지원합니다.
- 8·14턴 점검, 11턴 위기, 20턴 최종 심사. 신뢰 0이면 조기 실패, 최종 목표를 모두 달성해야 성공합니다.
- 도로 포함 서로 다른 3장, 나머지 5종은 3턴 안에 모두 등장. 다음 3턴의 카드와 위기 시점 공개.
- 포인터·키보드 포커스로 건설 후 예산·신뢰·전력·서비스·혼잡·환경을 확인. 건물 상태는 배지와 텍스트로도 표시합니다.
- 건설 쉬기도 한 턴을 소모하고 수입·유지비·주민 부담을 정산합니다. 물·사용한 땅 건설과 예산 부족은 차단합니다. 철거·되돌리기는 없습니다.
- 규칙 버전·임무·도시 코드와 행동 기록으로 같은 결과를 재현하고 이어합니다.

## 규칙과 저장 범위

초기 예산 14, 주민 신뢰 70. 건물은 중앙 도로와 연결된 도로에 상하좌우로 인접해야 연결됩니다. 물 3칸은 외곽에 배치하며 중앙 확장 통로는 보호합니다. 건설 후 해당 턴의 수입·유지비·부담·점검을 정산하므로 11턴 변화도 그 턴에 적용됩니다.

| 시설 | 효과와 제약 |
| --- | --- |
| 주택 (4) | 인구 3, 전력 수요 2. 도로 연결과 생활 서비스 필요 |
| 상점 (5) | 연결 시 일자리 4, 전력 수요 1. 정전 없이 연결 주민이 있을 때 수입 2 (주민 4명당 한 곳, 올림, 최대 3곳) |
| 공원 (3) | 환경 3, 물 인접 시 추가 2. 도로 없이 인접 주택 지원. 발전소 인접 주택은 진료소 필요 |
| 발전소 (4) | 연결 시 전력 6, 환경 −3, 연결 여부와 무관하게 유지비 1 |
| 진료소 (5) | 전력 수요·유지비 각각 1. 연결되고 정전이 없을 때 맨해튼 거리 2 이내의 연결 주택 지원 |
| 도로 (1) | 중앙 도로망에 연결된 칸마다 통행 용량 3. 떨어진 도로도 단절 부담을 만듦 |

기본 수입은 2이며 첫 임무의 10턴까지는 3입니다. 미지급 유지비는 예산 0에서 멈추고 미지급 비용 1당 신뢰 3을 잃습니다. 신뢰는 매 턴 3 회복(최대 100), 부담 1당 2 감소합니다. 4턴까지 부담은 0, 이후 부담은 전력 부족(최대 6) + 단절 시설·도로 수 ×2 + 실업 인구/3 올림 + 혼잡/3 올림입니다. 7턴부터는 미지원 인구/3 올림 + 오염 노출 인구/3 올림 + 음수 환경의 크기도 더합니다. 점검은 통과 시 예산 +4, 미달 시 신뢰 −12이며 한 번 놓쳐도 계속 복구할 수 있습니다.

| 임무 | 최종 목표 (공통: 단절·정전·실업·혼잡 0) | 11턴 변화 |
| --- | --- | --- |
| 연결되는 동네 | 인구 9 · 서비스 6 · 환경 0 · 예산 2 · 신뢰 35 이상 | 기본 수입 3 → 2 |
| 폭염 속 정원 도시 | 인구 9 · 서비스 9 · 환경 6 · 예산 3 · 신뢰 45 이상 | 주거 도시 전력 수요 +2 |
| 출근길의 약속 | 인구 12 · 서비스 9 · 환경 0 · 예산 4 · 신뢰 50 이상 | 주거 도시 통행 수요 +6 |

점수는 인구·서비스·일자리·환경·연결 도로·신뢰·예산에서 부족과 단절을 감점하는 보조 지표입니다. 점수만 높여서는 임무를 통과할 수 없습니다. 코드 `lesson`의 세 임무에 합법적인 20턴 승리 행동 기록을 모델 테스트로 검증했습니다. 모든 생성 코드의 승리 가능성이나 실제 사용자 난이도를 전수 증명하지는 않았습니다.

최근 완료 도시 10개와 진행 중 판 1개만 기기에 보관합니다. 성공 표시도 최근 10개 기록에서 계산하며 영구 업적을 따로 저장하지 않습니다. 이전 v1 완료 점수는 별도 표기하며 새 점수와 한 순위로 섞지 않습니다. 이전 진행 판은 새 규칙으로 해석하지 않고 이어하기를 제공하지 않습니다. 임무 선택은 새 도시 시작에 적용됩니다.

## 실행과 배포

Node.js 22 이상, 런타임 외부 의존성 없음.

```sh
npm run dev -- 0
npm test
npm run check
```

설계용 탐색은 `node tools/balance.mjs lesson`으로 실행할 수 있습니다. 폭 600·최대 20턴의 결정론적 탐색이며 결과를 파일·서버로 저장하지 않습니다. 승리 기록을 찾으면 가능성의 증거가 되지만 찾지 못하면 불가능하다는 뜻은 아닙니다. 빠른 회귀 검증은 `npm test`의 고정 승리 기록을 사용합니다.

개발 서버는 loopback에서 `dist/`만 제공합니다. `main`에 푸시하면 고정 SHA Actions가 시험·정적 검사 후 `dist/`를 GitHub Pages에 배포합니다. 저장소 Pages의 배포 소스는 GitHub Actions입니다.

## 기록과 개인정보

기록은 이 브라우저에만 저장하며 삭제할 수 있습니다. 계정, 분석 도구, 외부 AI API, 클라우드 저장, 전체 사용자 랭킹은 구현하지 않았습니다. CSP가 런타임 외부 연결을 막습니다. 공개 저장소에 정답·게임 규칙이 포함되므로 시험/공식 경쟁 판정 시스템이 아닙니다.
